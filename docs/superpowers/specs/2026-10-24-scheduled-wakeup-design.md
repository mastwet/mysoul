# 本体安排下一次自主唤醒

用户已认可单个 schedule_wakeup 工具方案并要求实施。普通主人聊天、自主活动及 owner 工作工具共用运行时日程服务。工具接受 after_seconds（30–86400 秒）、reason（1–300字符）及可选已有 owner goal_id。结果返回实际 UTC 时间和稳定引用；所有显示转换为本机时间。

只有一个有效下一次唤醒；新调用替换旧安排，使用稳定调用 ID 去重，不因回放延长。单 SQLite 事务核对 epoch/来源范围/自主开关/关联目标，然后保存请求和 next_initiative_at。模型不能开启自主功能、指定别人的范围或绕过预算。候选技能使用既有隔离工具环境，不能访问正式日程。

安排覆盖默认间隔；等待期间没有定时 LLM 调用。到点仍受主体占用、主人输入、模式、疲劳和预算约束，忙碌时保留一次待唤醒；触发后进入同一个主体上下文，携带时间和原始原因，原因标记为先前计划数据而非新指令。正常主人输入立即处理，不会无故丢失安排。关联任务取消/放弃、会话重置、自主关闭会撤销对应日程。重启保留未触发日程；已开始但中止的唤醒不自动重发。

工具回执只进入本轮或当前任务，不成为事实记忆/Recap/人格证据。心语展示安排时间、原因、替换/触发/取消/失败状态；只读页面不调用模型。

执行节奏区分轮内工具操作与轮间等待：保留现有有界执行预算和后台单步检查点，模型通过工具选择何时再醒，无阻塞 sleep，不创建第二个 agent。固定时间提醒与多事件队列不在此次范围。
