# 永久统一聊天与分级上下文压缩

日期：2026-10-23（Asia/Shanghai）
状态：用户已于2026-10-23确认设计；实施计划待审阅，尚未修改运行行为。
分支：codex/mysoul-v01。

## 用户目标

用户只看到一个永久聊天。主人输入、自主发言、任务进度及结果属于同一主体的连续经历，不因任务启动、重启或记忆压缩建立新会话。历史逐级压缩，保持长期连续性。参考 https://github.com/BDFFZI/Alife 。

## 上游依据与方案选择

已查看 Alife 的 README、MemoryManager.cs、MemoryConfig.cs 和 HistoryCompressor.cs（master，读取于上述日期）。MemoryManager 以等级和时间范围标识存档，先在快照中分析压缩，再核对范围锚点并替换上下文；提供读取存档内容的能力。默认普通消息阈值100、压缩70条；高层4个同级存档时合并较早3个；最高8级。

源码位置：
- https://github.com/BDFFZI/Alife/blob/master/Sources/Alife.Function/Alife.Function.Memory/MemoryManager.cs
- https://github.com/BDFFZI/Alife/blob/master/Sources/Alife.Function/Alife.Function.Memory/MemoryConfig.cs

候选：单层滚动摘要延续当前实现，改动小但容易反复改写全部记忆；按日期生成摘要易理解，但长短不均且会跨过当前话题；按容量和同级存档数量逐级合并，支持不同时间尺度和可追溯档案。选择第三种。借鉴机制，在现有 Python/SQLite 服务内独立实现。

## 唯一可见聊天

- 保留一个主人聊天入口，移除“最近消息”形成的会话列表外观，不提供新建/切换会话。
- 聊天、主动消息、任务的关键状态和最终结果进入统一时间轴。任务详情在原地卡片展开；工作区内仍可管理记忆、人格和设置。
- 普通工具调用、每次心跳、压缩过程不会刷成聊天消息；重要失败和需要主人介入的情况显示为相应任务卡片状态。
- 长历史通过稳定游标向上分页，加载旧消息时保持滚动位置。重新连接和重启不能重复插入已显示的项目。
- 原始聊天原文持久保留。后台压缩不把用户看到的历史替换成摘要，也不删除原文；压缩进度在记忆检查界面查看。

## 统一经历与顺序

使用不可变、单调递增的主人时间轴序号；保留源对象ID、来源类型、发生时间、原始证据引用和权限范围。时间戳不是唯一排序键。

主人交互和主动交互沿用既有事务落库，同时记录时间轴项目；任务卡片用稳定任务ID更新状态，不能因每次更新产生重复聊天条目。用户可见项目与用于压缩的经历分开建模：任务关键结果可进入经历，低层重复状态不反复进入摘要。

已有记录进行可重入迁移：采用时间及稳定ID建立确定顺序，记录迁移水位，不伪造缺失的正文或终结未完成任务。旧的100条状态截取不再决定历史可见范围。

## 分级压缩

- L0：近期完整经历，保留消息角色、来源、任务结果和相关证据。主人一轮与对应回复视作完整单元，不能在角色边界随意切断。
- L1：较早的连续L0经历组成阶段存档。
- L2–L8：相邻、同级且连续的存档组成更高层存档，时间跨度随等级增大。
- 每个存档保存等级、覆盖序号区间、起止时间、子节点ID、摘要、来源哈希、生成版本和发布状态；沿子节点一直能定位原文。
- 模型的常驻经历由互不重叠的有效存档节点及最新L0组成。父摘要替换其已覆盖子节点的常驻位置；父子不会同时作为完整连续记忆重复注入。
- 数量阈值和序列化后的实际上下文容量共同触发。优先合并最早可合并区段，保留最近完整对话；每次调度只处理一个有界批次。默认L0达到100个完整交互单元时压缩较早70个，至少保留最近8个完整单元；高层4个同级节点时合并较早3个。序列化输入达到预算75%时提前调度压缩，目标回落到55%以下；发布时仍检查实际总预算。一级摘要上限4000字符，高级摘要上限6000字符，拒绝比被替换内容更大的摘要。这些参数可配置，字符预算不等同于模型token窗口。
- 单个大结果采用明确的片段坐标，标记分段来源，不能静默截断。达到最高层后允许同层根存档合并并保留子节点链接，避免等级上限变成无界输入增长。
- 摘要按结构保留事实变化、偏好、承诺、未完成事项及其状态；区分主人事实、模型推断和虚构创作。任务取消/完成状态不能在后续压缩中恢复为待办。

## 与现有记忆、人格和执行的关系

分级存档负责经历的多尺度表示；Recap 保留为可编辑的当前工作摘要，突出当前关系、承诺和未完成事项，不再反复承担全部远期历史。当前Recap和历史档案按来源范围组装，避免整段重复。

长期检索继续使用既有 Memory 契约。检索可返回档案摘要及原文引用；需要细节时按范围展开，并受同一上下文预算约束。MemPalace不成为压缩发布的同步前提，待写队列继续可重试。

人格演化继续依据可追溯的原始证据窗口。新生成的摘要不是“新发生的经历”，不能再次计为独立人格证据或递归生成自我反馈。WORLD自动注入排除、受保护人格字段和活动任务固定版本保持既定契约。

用户可见的唯一主人聊天不取消内部来源隔离。群聊仍按既有Scope投影，不能向群模型注入私密主人聊天、Recap或其派生摘要；混合权限节点禁止发布。

## 发布、并发与恢复

复用主体准入和持久运行回执，不增加第二套并行生活循环。主人输入优先，压缩结果发布检查epoch、来源范围、父节点版本及清空失效代数。

生成发生在冻结快照中；发布时以一个SQLite事务保存新摘要、子节点关联及有效覆盖边界，成功后才调整常驻上下文。失败/超时、进程退出或版本冲突保留原来的有效节点和完整原文，支持从已保存阶段重试。稳定操作ID防止重复发布。

有界降级：压缩落后时保留数据和错误记录，禁止悄悄丢弃未覆盖内容。若必需上下文仍超过可用预算，则明确报告需要整理/恢复，而不是假装模型看到了全部历史。当前消息与必要任务状态优先保留；人格与固定指令、当前输入及运行任务必需状态先预留空间，然后使用不重叠的历史存档与近期原文；按剩余容量加入检索结果。最近8个单元若无法完整容纳，明确报告预算不足，不截断后声称成功。

清空当前Recap不删除聊天档案；清空的失效代数使旧压缩快照不能覆盖新状态。新增显式档案禁用/排除策略需独立明确后才能改变召回范围，不借本特性扩大删除语义。

## 验收

1. 普通交流→主动消息→任务关键结果在同一时间轴，角色和来源可辨，重启无重复。
2. 超过100条仍可分页读取历史，稳定游标、向上滚动和草稿不丢失。
3. L0→L1→L2以及最高层合并可重复验证；覆盖区间无缺口、无重叠，所有叶子能追溯原文。
4. 实际模型载荷包含近期原文及有效各层存档，不重复注入父子；预算触发早于输入溢出。
5. 大结果分段坐标完整，失败/超时/取消/重启和主人并发写入不推进错误覆盖。
6. 已取消目标不复活，虚构故事不被结构化标记为主人事实，摘要不反复成为人格新证据。
7. 群聊实际载荷不出现主人私密标记；来源权限沿压缩关系传播。
8. 旧数据迁移可重入、Recap手动编辑和失效行为一致；真实模型验证单独记录，跳过不算通过。

## 实施范围

本轮不引入Alife运行时、桌宠、多主体、多会话或新的外部发送权限。实现顺序建议：统一时间轴与迁移→档案与压缩事务→上下文及检索接入→聊天分页和卡片→恢复与真实验收。保持当前本机测试模式及三分钟自主检查配置。
